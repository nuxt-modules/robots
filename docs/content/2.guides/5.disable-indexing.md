## Introduction

Disabling certain environments of your site from being indexed is an important practice to avoid
SEO issues.

For example, you don't want your staging or preview environments to be indexed by search engines as they will cause duplicate
content issues as well as confuse end-users.

If you need to disable specific pages from being indexed, refer to the [Disabling Page Indexing](/docs/robots/guides/disable-page-indexing) guide.

## Disable Indexing Completely

In some cases, such as internal business tools, or sites that are not ready for the public, you may want to disable indexing completely.

You can achieve this by setting the `indexable` option to `false` in your site config.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  site: { indexable: false }
})
```

This does two things:

- The `robots.txt` blocks all crawlers with `Disallow: /`.
- Every page gets a `noindex, nofollow` robots meta tag and `X-Robots-Tag` header.

## Blocking Crawling Versus Blocking Indexing

The `robots.txt` controls crawling. The `noindex` directive controls indexing.
A crawler must fetch a page to read its `noindex` directive.
The `Disallow: /` rule stops the crawler before it fetches the page.
So a crawler that obeys `robots.txt` never sees the `noindex` directive.

This is safe for staging and preview environments that no other site links to.
Search engines seldom find these URLs, and `Disallow: /` also saves crawl budget.

It is not safe for a site that search engines already know about.
If another site links to a blocked URL, Google can still index the URL without its content.
Search Console reports these URLs as "Indexed, though blocked by robots.txt".
Google can also keep URLs that it indexed before, because it cannot read the new `noindex` directive.

::note
Do not block a page in `robots.txt` if you need search engines to see its `noindex` directive. Read the [robots.txt guide](/learn-seo/nuxt/controlling-crawlers/robots-txt) to learn more.
::

### Allow Crawling and Send Noindex

To remove a public site from search results, keep the site indexable and add a catch-all route rule.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/**': { robots: 'noindex, nofollow' },
  },
})
```

The `robots.txt` then allows crawling.
Every page gets the `noindex, nofollow` robots meta tag and `X-Robots-Tag` header, so crawlers can read the directive.
If you have a `public/robots.txt` file that disallows `/`, delete it.

## Handling Staging Environments

Staging environments are great for testing out code before it goes to production. However, we definitely don't want
search engines to index them.

To control the indexing of these sites we will make use of the `env` Site Config, which defaults to `production`.

```dotenv [.env]
NUXT_SITE_ENV=staging
```

Nuxt Robots will disable indexing for any sites which don't have a production environment, so feel free to set this
to whatever makes sense for your project.

## Handling Multiple Domains

If you deploy the same app to multiple domains (e.g. `mydomain.com` and `test.temp-domain.com`), you can disable indexing for specific hosts at runtime using a Nitro plugin.

```ts [server/plugins/robots-domain.ts]
export default defineNitroPlugin((nitroApp) => {
  nitroApp.hooks.hook('robots:config', (ctx) => {
    const host = ctx.event?.headers.get('host')
    if (host?.includes('staging') || host?.includes('test')) {
      ctx.groups[0].disallow = ['/']
    }
  })
})
```

This works for both SSR and prerendered sites. For static sites, set `NUXT_SITE_ENV` in your CI build instead (see [Handling Staging Environments](#handling-staging-environments)).

See the [Nitro Hooks](/docs/robots/nitro-api/nitro-hooks) documentation for more details on the `robots:config` hook.

## Verifying Indexing

To verify that your site is not being indexed, you can check the generated `robots.txt` file.
With `site.indexable: false`, it should look something like this.

```robots
User-agent: *
Disallow: /
```

With the catch-all route rule, the `robots.txt` allows crawling instead.

A robots meta tag should also be generated that looks like:

```html
<meta name="robots" content="noindex, nofollow">
```

For full confidence you can inspect the URL within Google Search Console to see if it's being indexed.

::tip
**Key points:** Use `site.indexable: false` or `NUXT_SITE_ENV` for staging environments. Use a catch-all `noindex` route rule to remove a public site from search results.
::
